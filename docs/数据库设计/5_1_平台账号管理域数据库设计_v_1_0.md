# 5.1 平台账号管理域数据库设计 v1.0

## 1. 文档说明

本文档用于设计多平台账号授权与管理域的数据库结构。该模块是整个系统的“凭据中心”，不仅支持当前阶段的抖音爬虫登录，还将扩展支持小红书、视频号、B站、Instagram、YouTube 等国内外平台的账号托管。

### 核心目标：
- **凭据集中化**：统一存储各平台的账号、密码、密钥。
- **Session 持久化**：将 Playwright/Puppeteer 采集所需的 Cookies 和 LocalStorage 存入数据库，实现多用户隔离与分布式采集。
- **发布授权**：为将来自动分发模块（发布内容）提供必要的 OAuth 令牌或授权上下文。
- **状态追踪**：实时记录账号是否在线、是否需要扫码重连。

统一命名建议：
- MySQL 表名前缀：`platform_`
- 主键统一使用 `BIGINT UNSIGNED`
- 时间统一使用 `DATETIME`
- 凭据数据必须经过应用层二次加密后再入库

## 2. 数据库设计总览

| 表名 | 用途 | 说明 |
| --- | --- | --- |
| `platform_accounts` | 平台账号主表 | 记录账号基本资料、平台类型及登录状态 |
| `platform_account_sessions` | 平台授权会话表 | 记录 Cookies、LocalStorage 等关键 Session 信息 |
| `platform_account_auth_logs` | 授权历史日志表 | 记录扫码、登录、失效及其原因的审计日志 |

## 3. 表设计详情

### 3.1 `platform_accounts` 平台账号主表

用途：存储各平台账号的核心元数据及当前活跃状态。

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键ID |
| `owner_user_id` | BIGINT UNSIGNED | 归属系统用户ID，对应 `iam_users.id` |
| `platform_code` | VARCHAR(32) | 平台编码：douyin, xiaohongshu, wechat_video, bilibili, etc. |
| `account_name` | VARCHAR(128) | 账号名称/登录ID（如手机号、邮箱、用户名） |
| `account_pwd_encrypted` | VARCHAR(512) | 加密后的密码（对称加密），可为空（若仅扫码授权） |
| `nickname` | VARCHAR(128) | 平台侧昵称 |
| `avatar_url` | VARCHAR(512) | 平台侧头像URL |
| `platform_uid` | VARCHAR(128) | 平台内部唯一标识（如 sec_uid 或 open_id） |
| `auth_status` | VARCHAR(32) | 授权状态：authorized (已授权), expired (已过期), need_reauth (需重新验证) |
| `account_type` | VARCHAR(32) | 账号类型：personal (个人号), business (企业号), agent (代理号) |
| `tags` | JSON | 账号标签，如 "科技", "娱乐" |
| `remark` | VARCHAR(500) | 用户备注 |
| `is_deleted` | TINYINT(1) | 逻辑删除标记：0否，1是 |
| `created_at` | DATETIME | 创建时间 |
| `updated_at` | DATETIME | 更新时间 |

**索引建议：**
- `idx_owner_platform`：`owner_user_id + platform_code`
- `uk_owner_platform_account`：`owner_user_id + platform_code + account_name` (业务唯一)
- `idx_platform_uid`：`platform_uid`

---

### 3.2 `platform_account_sessions` 平台授权会话表

用途：专门存储高频变化的 Session 数据。为了性能考虑，将其与主表分离。

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键ID |
| `account_id` | BIGINT UNSIGNED | 账号ID，对应 `platform_accounts.id` |
| `cookies` | JSON | 浏览器 Cookie 数组快照 |
| `local_storage` | JSON | 浏览器 LocalStorage 键值对快照 |
| `session_token` | TEXT | 获取到的 Token 或 API 密钥（若是 API 授权方式） |
| `user_agent` | VARCHAR(512) | 捕获该 Session 时使用的 User-Agent |
| `device_info` | JSON | 绑定的设备指纹或硬件信息 |
| `expires_at` | DATETIME | Session 理论失效时间 |
| `last_sync_at` | DATETIME | 最近一次从平台同步 Session 的时间 |
| `created_at` | DATETIME | 创建时间 |
| `updated_at` | DATETIME | 更新时间 |

**索引建议：**
- `uk_account_id`：`account_id` (一个账号维护一份最新 Session)

---

### 3.3 `platform_account_auth_logs` 授权历史日志表

用途：记录授权全生命周期事件，用于审计和排障（如：为什么这个号老掉线？）。

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键ID |
| `account_id` | BIGINT UNSIGNED | 账号ID |
| `event_type` | VARCHAR(32) | 事件类型：bind (初次绑定), refresh (Session刷新), expire (过期), revoke (解绑) |
| `event_status` | VARCHAR(32) | 状态：success, failed |
| `fail_reason` | VARCHAR(500) | 失败原因（如：验证码错误、环境异常） |
| `ip_address` | VARCHAR(64) | 授权时的IP地址 |
| `extra_data` | JSON | 原始回包或辅助排障信息 |
| `created_at` | DATETIME | 事件发生时间 |

**索引建议：**
- `idx_account_event`：`account_id + event_type`

## 4. 业务规则说明

1. **Session 注入策略**：
   采集模块启动 Playwright 前，查询 `platform_account_sessions`。若 `expires_at` 无效或状态为 `need_reauth`，则提示用户扫码。若有效，则通过 `context.add_cookies()` 和 `page.evaluate()` 注入 LocalStorage。
2. **Session 回收策略**：
   采集任务运行过程中，逻辑层应实时捕获 Cookie 变化。任务结束时，必须调用 `upsert` 逻辑将最新的 Session 更新回数据库，确保状态持续活跃。
3. **密码管理**：
   系统不直接使用明文密码进行登录（除非是某些需要密码的发布 API）。优先使用 Session 维持。

## 5. 结论

本设计通过主从表分离，实现了账号静态基础信息与动态 Session 信息的有效解耦。既保证了账户管理的清晰度，也为高频、高并发的爬虫采集提供了稳定、低冲突的数据支持。
